# App WSKEY 并发修复复核

范围：本地捕获 wskey 与 pt_pin、十五分钟合并、状态、手动清除。
不实现续期、换取 Cookie、身份验证或青龙上传。本次不发送京东请求，也不使用真实凭据。

## 已确认的问题与修复

通过合成数据重现以下旧版行为；不能据此确定用户手机实际发生的是哪一种。

- 两条请求交错：pin 请求读到空缓存后，wskey 请求完成；前者用旧快照写入空合并值。
- 过期清理：旧请求读到过期值，新请求写入 fresh wskey 后，旧请求把新值删除。
- 版本混用：旧脚本不接受新 pt_pin 缓存格式，异常处理删除共享 V1 数据。
- 无关异常：后续请求出现空 pt_pin 或冲突字段时删除之前抓到的完整凭据。

V2 将原始字段独立保存到 `jdAppWskeyCaptureV2` 与 `jdAppPinCaptureV2`，
派生视图保存到 `jdAppWskeyMergedV2`，状态、通知和观察记录也独立使用 V2。
正常捕获和查看不读取、不迁移 V1；明确清除操作会删除本插件 V1/V2 数据。
网页数据及旧 wskeyList 不读取、不修改。

捕获只写请求实际带有的字段，异常与过期逻辑不删除原始值。
已观察到的账号或 wskey 变化会记录不应继续配对的另一侧事件，等待另一侧重新捕获；
同请求完整凭据可以直接更新。合并前后重读来源，发生交错则有限次数重算，
状态也在写入后核对。持续变化报告 APP_BUSY，不承诺结果已稳定。

清除先改变代次，再删缓存。迟到原始记录的代次已撤销，不能参与合并。
本地存储没有原子事务：清除期间先暂停 App 流量，待请求结束再清除才能确保物理移除；
同字段的并发写入不保证时间顺序。未声称无锁实现提供串行化或线性一致性。

## 数据与权限检查

HTTPS 入口保持原有四个精确域名/路径，没有扩大抓取范围。
只提取 wskey、pin、pt_pin，输出统一为 `pt_pin=…; wskey=…;`，不把 pin_hash 当账号。
输入格式错误不回显内容；通知只显示固定状态，状态记录仅含布尔值、时间和状态码。
原始和合并凭据只保存在 Loon 本地。没有网络、日志、进程、动态代码、远程算法或运行依赖。

十五分钟限制仍独立作用于每侧。过期原始值保留到手动清除，这是为了避免竞争删除；
状态与合并在执行时重新判断过期，BoxJs 本身不会触发。切换账号前必须清除。
时间接近不能证明身份；跨请求仍为 cross-request-unverified，同请求仍未验证服务端有效性。

## 验证

本地合成测试 259/259 通过，静态 AST 检查发现数为零。
包括两种捕获顺序、每个存储操作前后的交错、旧过期读取返回前新值写入、
异常请求不破坏有效结果、V1 写删隔离、损坏单侧恢复、账号变化与重新配对、
过期、部分写入失败、持续变化收敛上限，以及清除穿插于每个捕获存储边界。
完整打包脚本还在独立 VM 中交错执行，检查不改变请求、结束回调一次、无凭据日志通知。

断网容器结果及源码哈希以 `isolation-report.json`、`test/isolation.tap` 为准；
验证使用固定青龙镜像、非 root、只读根目录、禁网、移除 capabilities、禁止提权，
无宿主 bind 挂载，仅有基础镜像声明的全新匿名 /ql/data 卷。测试包仅包含 11 个明确列出的文件，
网络、进程与文件写入 API 被监测阻断；没有导入真实 Cookie、面板数据或宿主目录。
