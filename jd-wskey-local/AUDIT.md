# App WSKEY 本地合并复核

范围：捕获 wskey 与 pin/pt_pin、十五分钟内本地合并、查看状态和清除暂存。
不实现续期、换取 Cookie、服务器身份验证或青龙上传。没有执行用户提供的真实请求，
未把真实凭据、完整 URL 或设备字段写入源码、测试或报告。手机兼容性及凭据有效性仍待实测。

## 数据路径与身份限制

接受 `blackhole.m.jd.com`、`perf.m.jd.com` 的 HTTPS 请求，以及 `sh.jd.com/j/<标识>`、
`mars.jd.com/log/sdk/v2` 的精确 HTTPS 路径。新加入的 mars 入口用于补充请求中的 pt_pin。
Loon MitM 按域名生效，脚本仅处理指定入口；无 `*.jd.com` 通配。

只提取 Cookie 头中精确命名的 wskey、pin、pt_pin。忽略 pt_key、pin_hash 和设备字段。
wskey、pin 分别写入 `jdAppWskeyCaptureV1`、`jdAppPinCaptureV1`，
输出写入 `jdAppWskeyMergedV1`。跨请求输出标记 `cross-request-unverified`；同请求输出标记
`same-request-unverified`，均不代表京东登录校验通过。观察记录、状态和通知没有凭据或账号原文。

本次修正保存格式：原始暂存中的 `credential.cookie` 与合并结果中的 `cookie` 都输出
`pt_pin=…; wskey=…;`。两个账号字段同时出现时校验解码后的一致性，并优先保留 `pt_pin` 原编码。
旧 `pin` 请求仍兼容；`pin_hash` 不作为账号。旧缓存只接受上版严格格式，下一次脚本执行时迁移，
保留时间与未核验标记，不延长十五分钟期限。迁移前先清除旧合并结果，写入失败不能报告成功。

时间窗口不能证明两个字段属于同一账号。切换账号前需要清除暂存；只有已观察到的 pin 或 wskey 变化
才能触发另一侧记录失效。无法承诺自动识别所有账号切换。本版本按用户要求允许这种明确标注未核验的配对，
不把结果接入正式任务验收，也不据此放开部署门槛。

每侧独立过期，结果期限取较早的一侧。写入新字段前先清除旧结果，部分写入失败报告失败；
完全不可写时无法保证旧值已删除。异常字段冲突或损坏记录清除敏感缓存。
无 console、HTTP 客户端、动态代码、系统命令、外部算法或运行依赖。

## 验证

本地 45/45 合成测试通过，静态 AST 检查发现数为零。静态检查只补充人工复核，不是普遍安全证明。
固定青龙镜像的断网容器中同样 45/45 通过：非 root、只读根目录、无宿主 bind 挂载、
移除所有 capability、禁止提权。监测到的网络、进程和文件写入禁用能力调用为零，10 个测试包文件哈希一致。
基础镜像声明的 `/ql/data` 使用全新 Docker 匿名卷，没有导入宿主数据或凭据。
本次镜像摘要、源码与测试包哈希及原始结果见 `isolation-report.json` 和 `test/isolation.tap`。

覆盖：两种捕获顺序、perf/mars 单独提供 pt_pin、同请求 pt_pin 归一化、pin_hash 不冒充账号、
中英文与编码、Cookie 多种头表示及冲突值、伪造域名与无关路径、账号和密钥变化、每侧独立过期、
重复触发通知限流、部分存储写入失败、异常下一请求也清除过期结果、旧网页数据隔离和结束回调仅一次。
生成的完整脚本也模拟多次 Loon 执行共享存储，确认能合并、请求不变、通知不泄露凭据；
网络、进程、日志等能力在测试中禁用。
新增覆盖：`pt_pin` 编码保留及优先级、旧 `pin` 输入兼容、同请求及跨请求旧缓存迁移、迁移不延长期限、
损坏旧记录拒绝、部分迁移写入失败和完整打包脚本手动查看时的迁移。
